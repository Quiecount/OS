# 团队共享开发环境搭建指南（双方案版）

> 目标：三人共用**同一套 openEuler 开发环境**——代码、编译、探针测试都在一套环境里完成
> 双方案：A 共享机主虚拟机（免费）/ B 云虚拟机（付费），用法大同小异，按情况二选一
> 更新：2026-11-06

---

## 〇、先选方案：一张表看清利弊

| 对比维度 | 方案 A：共享机主的虚拟机 | 方案 B：云虚拟机 |
|---|---|---|
| 花费 | **0 元** | 约 ¥30–100/月（**学生认证后可低至个位数/月**，以官网活动为准） |
| 机器在哪 | 机主笔记本（32G）的 VirtualBox 里 | 云厂商机房，7×24 在线 |
| 求不求人 | **要求机主同意**：长期开机 + 三人远程连她的私人电脑 | **不求任何人**：花钱买一台完全独立的机器 |
| 网络要求 | 路由器互通或 Tailscale；**受校园网隔离影响** | 公网 IP 直连，**在任何网络下都能连**（学校/家里/热点） |
| 可用时段 | 机主开机才有 | 全天候，随时 |
| 性能上限 | 32G 内存随取随用（还能后期开双虚拟机做多内核适配，加分项） | 看买的规格：2C4G 够开发，预算够上 4C8G |
| 性能数据质量（评分项） | 笔记本环境有噪声：宿主程序抢资源、降频 | 固定环境更稳，**答辩的 benchmark 数据更可信** |
| 主要风险 | 机主关机 = 全队停摆；占用她人电脑需要信任 | **忘退订会一直扣费**；数据在公网需做安全加固 |
| 附加收获 | 无 | 顺带学会云服务器运维（简历能写一笔） |

**怎么选**：

- 方案 A 为主（全程免费），赛前一个月再开一台 B 采性能数据（几十块）
- 全程方案 B：总价百来块，买省心买和谐
- 机主"愿意但要求随时能收回电脑" → A（日常）+ B（答辩数据）组合，最常见打法

## 一、原理篇：共享开发环境是怎么回事（两方案通用，先读懂再动手）

### 一句话版本

**开发环境只有一套 Linux（openEuler）**。方案 A 里它跑在机主的 VirtualBox 里；方案 B 里它是云厂商的一台服务器。三个人的 VSCode 通过 SSH 连到这**同一台机器**——你写的每行代码、跑的每条命令，都发生在这台机器上，你自己的电脑只是个"显示器"。

### 图示

```
你的电脑（8G 游戏本）──┐   三人各自只跑一个 VSCode 窗口，
队友B的电脑 ──────────┤   自己电脑上不装任何开发环境
                      │
        └── SSH 加密连接 ────────────────┐
                                       ▼
     方案A：机主电脑(32G) → VirtualBox → openEuler 虚拟机
     方案B：云厂商机房 → openEuler 云服务器（公网 IP）
              （代码、编译、探针、测试 全部发生在这里）
```

### 三个关键认知（看懂就不迷惑）

1. **代码从敲下那一刻就存在远端机器里**。你在 VSCode 里打开的文件夹是"远端的文件夹"，不是你电脑的——不存在"写完再传过去"，写完直接在下方终端里编译测试，零距离。
2. **吃的是共享环境的资源**。你的 8G 游戏本全程只负责显示一个 VSCode 窗口，负载约等于开个网页。
3. **连接地址只差一行**：方案 A 里机主本人填 `localhost`、队友填机主 IP；方案 B 里三人都填云服务器的公网 IP，完全平权。

### 日常的一天长什么样（建立预期）

1. 启动共享环境（A：机主开机开虚拟机 / B：本来就 7×24 在线，跳过）
2. 各自打开 VSCode → 连接 → 左下角变绿色 `SSH: teamvm` 就是连上了
3. 各改各的模块文件 → 在 VSCode 内置终端里 `make`、跑探针、看输出
4. 收工：commit + push 到自己的 git 分支
5. 打快照（A：VirtualBox 快照 / B：云控制台一键快照）

### 协作规矩（共用一台机器的代价，提前约定）

- **重启 / 装内核组件 / 大规模压测前，群里喊一声**——你们仨在同一个系统里，你一重启队友就闪断
- 各用各的 Linux 账号，日常**不要用 root 干活**
- **git 每天必 push**：既是备份，又是比赛要求的"过程性资料"，一举两得

## 二、方案 A：共享机主虚拟机（免费方案）

### A.0 利弊清单

**利**：零成本；32G 内存管够，五场景压测不用缩参数；后期可开双虚拟机（24.03 + 22.03 双内核版本）直接覆盖评分"多平台适配"加分项；数据不出校。

**弊与应对**：占用机主私人电脑、要求长期开机、三人远程连入她的机器。
**跟机主沟通的话术要点**："代码全在 git 上，你的电脑只是编译测试环境，你随时可以关机收回，什么都不会丢；负载很低（探针项目编译量是几十行的小程序），不会像跑游戏那样发热；你的系统和文件我们碰不到，我们只在虚拟机里活动。"

### A.1 虚拟机确认 SSH 服务（机主做）

```bash
systemctl status sshd        # 应为 active (running)
# 没装/没启动就：
dnf install -y openssh-server
systemctl enable --now sshd
ip addr                       # NAT 模式下虚拟机 IP 一般是 10.0.2.15
```

### A.2 VirtualBox 端口转发

虚拟机关机 → 设置 → 网络 → 网卡1（NAT）→ 高级 → 端口转发 → 添加：

| 名称 | 协议 | 主机端口 | 子系统端口 | 主机IP | 子系统IP |
|---|---|---|---|---|---|
| ssh | TCP | 2222 | 22 | 留空 | 留空 |

> 2222 哪来的：把机主电脑的 2222 端口接到虚拟机的 22 端口（SSH 默认端口），相当于在墙上开个洞。

开机后机主自测：`ssh -p 2222 root@localhost` 能进 = 成功。

### A.3 Windows 放行 + 查机主 IP（机主做，管理员 PowerShell）

```powershell
New-NetFirewallRule -DisplayName "TeamSSH" -Direction Inbound -Protocol TCP -LocalPort 2222 -Action Allow
ipconfig        # 记下 IPv4 地址，如 192.168.1.100
```

### A.4 队友连入测试（最易翻车的一步）

队友电脑（Win10/11 自带 ssh）：

```powershell
ssh -p 2222 root@192.168.1.100
```

⚠️ **校园网/宿舍 WiFi 客户端隔离大坑**：许多校园网禁止设备互访，表现为 ping 机主 IP 不通。解法按顺序试：

1. **手机开热点**，三人连同一热点（最快最稳；SSH 是纯文本，流量 KB 级，耗不了多少）
2. **Tailscale**（https://tailscale.com，免费）：三人各装各登录，自动组成虚拟局域网，每台电脑拿到固定 `100.x.x.x` IP——**各在家中也照样互连**，SSH 配置里 HostName 换成机主的 Tailscale IP
3. 都不行 → 放弃方案 A，转方案 B

### A.5 每人建独立 Linux 用户（机主在虚拟机里做）

```bash
useradd -m -G wheel carol && passwd carol    # 机主本人
useradd -m -G wheel alice && passwd alice    # 队友A
useradd -m -G wheel bob   && passwd bob      # 队友B
```

（`wheel` 组 = 有 sudo 权限）root 密码机主掌管；各用各的账号。

### A.6 VSCode Remote-SSH（每人各自做）

机主本人的 `C:\Users\<你>\.ssh\config`：

```
Host teamvm
    HostName localhost
    Port 2222
    User carol
```

队友的配置（只差 HostName 一行）：

```
Host teamvm
    HostName 192.168.1.100     # 机主的局域网 IP；用 Tailscale 就换成 100.x.x.x
    Port 2222
    User alice                 # 换成自己的用户名
```

使用：`F1` → connect → **Remote-SSH: Connect to Host...** → 点 `teamvm` → 首次连接问 `Are you sure...` 输 `yes` → 输密码 → **左下角变绿色 `SSH: teamvm` = 连上了** → 打开文件夹（如 `/home/carol/osmedic`）开始干活。

### A.7 防翻车三件套（方案 A 专属）

1. 每天收工 **VirtualBox 打快照**
2. 机主笔记本：电源"接通电源时永不睡眠"+ 设置 Windows 活跃时间避开自动重启
3. git 每天必 push

## 三、方案 B：云虚拟机（付费方案）

### B.0 利弊清单

**利**：不求人（机器完全是队里的）；7×24 在线、任何网络直连（校园网隔离？不存在的）；环境固定 → 性能开销数据更可信；三人平权，顺便学会云运维。

**弊与对策**：

| 弊 | 对策 |
|---|---|
| 要花钱（¥30–100/月） | **先做阿里云学生认证**（"云工开物"高校计划：高校学生认证后领 **¥300 无门槛券**，可抵扣 ECS/轻量服务器等，券 1 年有效）——¥300 基本能覆盖整个比赛周期，接近免费 |
| 忘退订会持续扣费 | 买完当天在手机日历设"比赛结束 → 退订"；控制台里设**费用告警** |
| 便宜款"共享型"实例有 CPU steal 噪音 | 选**通用型/独享型 2C4G**，避开"共享型/x86 突发"——CPU steal 会污染调度类指标（runqlat 场景） |
| 数据在公网 | 做下面 B.3 的安全三件事 |

### B.1 购买流程（详细）

1. **选厂商：阿里云**（推荐理由：openEuler 官方镜像直接在 ECS 公共镜像里、控制台对新手友好、学生权益实在）。备选腾讯云。**正确顺序**：注册 → 实名认证 → **学生认证领 ¥300 券**（https://university.aliyun.com，云工开物计划）→ 再进 ECS 购买页。⚠️ 券不可与产品折扣叠加、部分商品只能抵一次，下单时确认"本单可用 ¥300 券"再付款
2. 购买 ECS 时关键选项：

| 配置项 | 建议值 | 说明 |
|---|---|---|
| 地域 | 就近（华东选上海/杭州） | 延迟低 |
| 机型 | **通用型/独享型 2C4G**（预算宽裕上 4C8G） | 避开共享型，防 CPU steal |
| 镜像 | **公共镜像 → openEuler 24.03 LTS** | 官方镜像，免安装，开机即用 |
| 系统盘 | 40–60G | 项目绰绰有余 |
| 带宽 | 按流量计费即可 | SSH 流量 KB 级，花不了几块钱 |
| 购买时长 | 按月，别一次买半年 | 灵活，随时退 |

3. 下单时设置 root 密码（**强密码**：大小写+数字+符号，12 位以上）→ 等 1–2 分钟开机 → 在控制台复制**公网 IP**

### B.2 第一次登录（三人各自，从自己的电脑）

```powershell
ssh root@公网IP
# 首次连接问 Are you sure... 输 yes → 输 root 密码
```

能进 = 通了。方案 B **不需要端口转发、不需要防火墙规则、不受任何局域网限制**——这就是它省心的地方。

### B.3 安全三件事（公网暴露，必做）

1. **建个人用户，日常不用 root**：

```bash
useradd -m -G wheel alice && passwd alice
useradd -m -G wheel bob   && passwd bob
useradd -m -G wheel carol && passwd carol
```

2. **安全组只放行 SSH**：云控制台 → 安全组 → 入方向规则**只保留 22 端口**（其他端口用不到就别开）；"放行全部端口 0.0.0.0/0"是红线，不要出现
3. **打快照**：控制台 → 磁盘/实例 → 创建快照（每周一次 + 每天重大改动后一次）

### B.4 装开发工具链（阶段 0 清单，一次装齐）

```bash
dnf update -y
dnf install -y bpftrace bcc-tools libbpf-devel clang llvm make git stress-ng fio sysstat kernel-devel vim
```

### B.5 VSCode Remote-SSH（三人配置完全相同）

```
Host teamvm
    HostName 公网IP        # 云控制台复制的那个
    Port 22
    User alice             # 各换成自己的用户名
```

用法与方案 A 完全一样：F1 → connect → teamvm → 绿色角标即成功。

### B.6 云主机专属省钱/防坑提醒

- **费用告警**：控制台设"余额低于 ¥X 短信提醒"，防止欠费停机
- **比赛结束立刻退订/释放**：日历提醒，别让机器闲置吃钱
- **进阶可选**（会折腾再折腾）：SSH 改非 22 端口、密钥登录代替密码——不做也能安全运行，做好上面三件事就够比赛用
- 云主机上**别存与项目无关的个人文件**

## 四、两方案的组合策略（最省心打法）

1. **现在（开发期，11–12 月）**：A 或 B 选一个当主力
2. **赛前一个月（采性能数据期）**：无论主力是哪个，建议**固定在一台云主机上集中采集** benchmark 数据（答辩数据环境一致、可信）；若主力已是 B，跳过
3. **切换无缝**：代码全在 git 上，从 A 迁到 B = `git clone` + `dnf install`（B.4 那条命令），10 分钟
4. **git 是一切的保险**：无论 A 还是 B，环境都可能死，git 上的代码和提交记录死不了——这也是比赛的"过程性资料"评分项
