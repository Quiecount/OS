# 场景 1–2：实现、阈值与性能评测

## 功能与数据口径

`syscallhot` 挂载 `raw_tp/sys_enter` 和 `raw_tp/sys_exit`。内核用 TID 关联进入和退出，按进程 PID + syscall ID 聚合完成次数、耗时总和与 26 桶延迟直方图；用户态每秒输出 Top-N 的频率、平均延迟与 P99 桶上界。默认规则是频率至少 1000 次/秒、超过配置基线（默认 1000 次/秒）的 10 倍、且进入 Top-N，输出 `SYSCALL_HOTSPOT`。`--baseline-rate`、`--min-rate`、`--top` 可调整。默认基线仅为演示起点；正式比较需要在同一机器、同一负载下先采正常态基线，再输入 `--baseline-rate`。

`cpuwatch` 挂载 `raw_tp/sched_switch`、`raw_tp/sched_wakeup` 和 `raw_tp/sched_wakeup_new`。按线程记录运行起点和就绪队列进入时间，按进程聚合运行时间和等待直方图。`cpu_percent_one_core` 以一个 CPU 核的容量为 100%，多线程进程可以大于 100%。连续超过 80% 达 10 秒时输出 `CPU_HOG`。全局 runqlat P99 桶上界超过配置基线（默认 1000 µs）的 5 倍、窗口至少 20 次样本时输出 `SCHED_DELAY`。`--baseline-p99-us` 可调整。

P99 是 2 的幂直方图**桶上界估计**，并非精确百分位。`runq_wait_ms` 统计就绪队列等待，不包含主动睡眠、磁盘 I/O 阻塞；这比把所有 off-CPU 时间当调度延迟更准确。两支探针均排除加载器本身的 PID。当前版本是整机观测，不区分容器，也没有保存跨运行的自学习基线。

## 复现与验收

```bash
make check
sudo bash scripts/stage2-two-scenarios.sh
```

脚本编译 `faults/syscall_bomb.c`，调用 `fstatat` 制造系统调用热点；用 `stress-ng --cpu 1` 制造持续 CPU 占用，再用 `stress-ng --cpu 8` 在四核 VM 制造调度拥堵。验收检查 JSON 解析、`SYSCALL_HOTSPOT`、`CPU_HOG`、`SCHED_DELAY`、调度指标和诊断必需字段，成功时输出 `STAGE2_TWO_SCENARIOS_OK`。拥堵测试把 P99 基线设为 100 µs，便于在目标 VM 稳定复现，不能当作实际正常态基线。

## 性能指标与“优秀”目标

本地《2026 华东区域赛技术方案》第 3 页给出应用开发赛道参考权重：代码 30%、文档 30%、教学价值 10%、规范 10%、演示答辩 20%；**没有给出 CPU、内存、时延或吞吐的“优秀”数值线，也没有规定可由开发者自行计算的官方分数**。项目开发计划中的 40/30/15/15 是内部策略，不能称为官方评分。

为便于迭代，本项目暂用下列**自定工程目标**；这些数值不是赛方标准：

| 指标 | 当前工程目标 | 测量方式 |
|---|---:|---|
| 探针引起的 syscall 与 CPU 负载吞吐下降 | ≤5% | 同机同负载，开关探针配对 3 次，比较吞吐中位数 |
| 由吞吐倒数推算的每操作平均耗时增加 | ≤5.3% | `baseline_rate / monitored_rate - 1`；仅是等效均值，不是 P99 |
| 加载器进程用户态 CPU | ≤5% 单核 | `/proc/PID/stat`，采样期间时钟滴答 |
| 加载器 RSS | ≤64 MiB | `/proc/PID/status`，采样最大值 |
| 两场景三个异常注入识别 | 3/3 | `stage2-two-scenarios.sh` |

定值 5% 是项目组的低干扰目标，需在目标 VM 上复测。`bench-two-scenarios.py` 输出原始每轮数据及中位数到 `output/benchmark/result.json`。主机调度、虚拟机竞争、负载持续时间会影响结果；比较需要相同 VM 配置、同一时段、交替运行开关组。`stress-ng` 的 bogo ops 是其自身吞吐单位，不能跨版本或跨机器直接比较。加载器 CPU 不等于内核 BPF CPU；吞吐差异才包含内核探针影响。

```bash
sudo python3 scripts/bench-two-scenarios.py
# 快速单轮检查（不能用作最终性能结论）
sudo TRIALS=1 python3 scripts/bench-two-scenarios.py
```
