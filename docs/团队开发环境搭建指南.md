# 团队开发环境搭建指南（各自本机开发版）

> 目标：三人**各自在自己电脑上**跑一套 openEuler 开发环境——代码、编译、探针测试都在本机虚拟机里完成，代码同步靠 git
> 结构：主力方案 = 本机 Hyper-V 虚拟机（免费，推荐）/ 备选方案 = 云虚拟机（赛前集中采性能数据用）
> 更新：2026-11-08（原"共享环境双方案版"作废：团队决定不共享，各自本机开发；VirtualBox 替换为 Hyper-V）

## 〇、方案总览

| 对比维度 | 主力：本机 Hyper-V 虚拟机 | 备选：云虚拟机 |
|---|---|---|
| 花费 | **0 元** | 约 ¥30–100/月（**学生认证后可低至个位数/月**，见 §三） |
| 机器在哪 | 自己电脑（32G×2 + 16G×1） | 云厂商机房，7×24 在线 |
| 求不求人 | **不求任何人** | **不求任何人** |
| 可用时段 | 自己开机就有 | 全天候，随时 |
| 性能上限 | 32G 机器管够；16G 机器够用，压测时紧张（见 §2.2 内存表） | 看规格：2C4G 够开发 |
| 性能数据质量（评分项） | 笔记本环境有噪声：宿主程序抢资源、降频 | 固定环境更稳，**答辩的 benchmark 数据更可信** |

| 主要风险 | 本机环境炸了 | **忘退订会一直扣费**；数据在公网需做安全加固 |

**打法**：开发期三人各自用本机 Hyper-V 虚拟机；赛前一个月开一台云主机，benchmark 数据统一在云上采（环境一致、数据可信），完赛退订。

## 一、原理篇：各自本机开发是怎么回事

### 一句话版本

**开发环境每人一套**：每人自己电脑上跑一个 openEuler 24.03 虚拟机（Hyper-V），VSCode 通过 SSH 连**自己本机的虚拟机**。你写的每行代码、跑的每条命令都发生在自己的 VM 里；三人之间的代码同步**只靠 git**。

### 图示

```
成员A（32G）── Hyper-V ──► openEuler 24.03 VM    ┐
成员B（32G）── Hyper-V ──► openEuler 24.03 VM    ├─── 同步靠 git（每人每天必 push）
成员C（16G）── Hyper-V ──► openEuler 24.03 VM    ┘
（赛前一个月：三人在同一台云主机上集中采集性能数据）
```

### 三个关键认知（看懂就不迷惑）

1. **每人一套环境，互不影响**——不存在"队友重启我闪断"，也不用再求任何人长期开机。
2. **VSCode 连的是本机虚拟机**，localhost 级延迟，体验和远程共享版完全一样：打开的文件夹是虚拟机里的文件夹，写完直接在下方终端里编译测试。
3. **git 是唯一的同步手段**：VM 会坏、电脑会换、环境会迁到云上，git 上的代码和提交记录死不了——所以**每天必 push**（也是比赛"过程性资料"评分项）。

### 日常的一天长什么样

1. 开机 → 打开 Hyper-V 管理器 → 启动虚拟机
2. 打开 VSCode → 连接 → 左下角变绿色 `SSH: openeuler` 就是连上了
3. 改代码 → 在 VSCode 内置终端里 `make`、跑探针、看输出
4. 收工：commit + push 到自己的 git 分支
5. 打检查点（Hyper-V 的"快照"，见 §2.7）

### 协作规矩（各自开发版）

- **git 每天必 push**：同步、备份、比赛过程性资料三合一
- **环境统一**：openEuler 24.03 LTS（内核 6.6），装包清单统一（§2.4 那条命令）
- **环境级改动群里同步**：换内核版本、改 VM 配置、大规模压测参数这类会影响测试数据的改动，动手前说一声
- 各自记录自己的环境参数（CPU/内存/VM 配置），测试数据注明在什么环境采的

## 二、主力方案：本机 Hyper-V 虚拟机

### 2.0 前提检查（2 分钟）

1. **Windows 版本**：`Win+R` → `optionalfeatures` → 看"Hyper-V"是否存在。
   - 专业版 / 教育版 / 企业版：有完整 Hyper-V，按本方案走
   - 家庭版：没有完整 Hyper-V → 装 **VMware Workstation**（个人使用免费）或 VirtualBox 代替，虚拟机**里面**的步骤（§2.3 起）完全一样，只是建虚拟机的界面不同
2. **BIOS 虚拟化已开**：任务管理器 → 性能 → CPU → 右侧"虚拟化：已启用"。未启用则进 BIOS 开 VT-x（Intel）/ AMD-V / SVM
3. **磁盘**：虚拟机磁盘放剩余空间 ≥100G 的盘（C 盘空间紧张就别放 C）

### 2.1 下载 ISO

openEuler 24.03 LTS x86_64 DVD（约 4G）：

> https://repo.openeuler.org/openEuler-24.03-LTS/ISO/ → 选 `openEuler-24.03-LTS-x86_64-dvd.iso`

### 2.2 创建虚拟机

**图形界面方式**（Hyper-V 管理器，开始菜单搜"Hyper-V"）→ 新建 → 虚拟机：

| 配置项 | 值 | 说明 |
|---|---|---|
| 代数 | **第 2 代** | 必选第 2 代 |
| 内存 | 见下表 | 后期可改，改内存需先关机 |
| 处理器数 | 4 | |
| 磁盘 | 60–100G，动态扩展 | 放空间大的盘 |
| 网络 | 默认交换机 | NAT 型，宿主机可直接 SSH 进虚拟机 |
| 安装选项 | 稍后挂 ISO | 先建 VM 再配 |

**内存分配表**（按宿主机内存对号入座）：

| 宿主机内存 | 虚拟机内存 | 说明 |
|---|---|---|
| 32G | 8192 MB（宽裕可 16G） | 五场景压测不用缩参数 |
| 16G | 日常 6144 MB，**压测前调成 8192 MB** | 防止宿主机 Windows 内存不足；压测时关掉宿主里的大型程序 |

创建完成后**必做两步**（第一坑就在这）：

1. 设置 → 安全 → **取消勾选"启用安全启动"**——不关的话装不上系统（黑屏/不引导）
2. 设置 → DVD 驱动器 → 映像文件 → 选下载的 ISO

**PowerShell 一条龙方式**（管理员，等价于上面全部操作）：

```powershell
New-Item -ItemType Directory -Force E:\HyperV    # 换成你放虚拟机的盘
New-VM -Name openEuler24 -Generation 2 -MemoryStartupBytes 8GB `
  -NewVHDPath E:\HyperV\openEuler24.vhdx -NewVHDSizeBytes 64GB -SwitchName "Default Switch"
Set-VMProcessor -VMName openEuler24 -Count 4
Set-VMFirmware -VMName openEuler24 -EnableSecureBoot Off
Add-VMDvdDrive -VMName openEuler24 -Path "D:\ISO\openEuler-24.03-LTS-x86_64-dvd.iso"   # ISO 路径换成自己的
Set-VMFirmware -VMName openEuler24 -FirstBootDevice (Get-VMDvdDrive -VMName openEuler24)
```

> 16G 机器把 `8GB` 改成 `6GB`；需要调整时：关机 → 设置 → 内存。

### 2.3 安装 openEuler

启动虚拟机 → 图形安装向导：

- 软件选择：**最小安装**（够用；不选图形界面）
- 设置 root 密码（强密码）
- 装完重启 → 登录 → `ip addr` 记下虚拟机 IP（默认交换机一般是 `172.x.x.x`）

### 2.4 装开发工具链（阶段 0 清单，一次装齐）

```bash
dnf update -y
dnf install -y bpftrace bcc-tools libbpf-devel clang llvm make git stress-ng fio sysstat kernel-devel vim
```

> 个别包可能需要添加 EPOL 源，报"找不到包"时先 `dnf update -y` 再试。

### 2.5 SSH 连通（本机方案不需要端口转发）

```bash
systemctl status sshd        # 应为 active (running)
# 没装/没启动就：
dnf install -y openssh-server
systemctl enable --now sshd
```

宿主机 PowerShell 自测：`ssh root@虚拟机IP` 能进 = 通了。

> Hyper-V 默认交换机是 NAT 型，宿主机**直连虚拟机 IP** 即可——不需要 VirtualBox 时代那套"端口转发"配置。
> ⚠️ 默认交换机的 IP 段在宿主机重启后可能变化，哪天连不上就进虚拟机重新 `ip addr` 看一眼新 IP。

### 2.6 VSCode Remote-SSH

装好 Remote-SSH 扩展，编辑 `C:\Users\<你>\.ssh\config`：

```
Host openeuler
    HostName 172.x.x.x     # 换成自己虚拟机的 IP
    Port 22
    User root
```

使用：`F1` → **Remote-SSH: Connect to Host...** → 点 `openeuler` → 首次连接问 `Are you sure...` 输 `yes` → 输密码 → **左下角变绿色 `SSH: openeuler` = 连上了** → 打开文件夹（如 `/root/osmedic`）开始干活。

> 本机单人虚拟机直接用 root 可以接受（eBPF 探针加载本来就需要 root）。想养成好习惯可以 `useradd -m -G wheel <名字> && passwd <名字>` 建个人用户。

### 2.7 快照（Hyper-V 里叫"检查点"）

- 每天/每个阶段收工：Hyper-V 管理器 → 右键虚拟机 → **检查点**
- 或 PowerShell：`Checkpoint-VM -Name openEuler24 -SnapshotName "阶段0完成"`
- **装内核组件、换内核版本、大规模压测前必打**，翻车 30 秒回滚

### 2.8 常见坑速查

| 症状 | 原因 / 解法 |
|---|---|
| 虚拟机启动黑屏 / 找不到启动盘 | 安全启动没关（§2.2 必做两步）或 ISO 没挂上 |
| bpftrace / bcc 装不上 | 先 `dnf update -y`；仍报找不到包则启用 EPOL 源 |
| 编译报缺内核头文件 | 装 `kernel-devel`（版本要和 `uname -r` 对得上） |
| 压测时虚拟机 OOM / 宿主机卡死 | 虚拟机内存 ≥8G；16G 宿主机压测前把 6G 调成 8G，关掉宿主大型程序 |
| 想在 Windows 里直接编译 eBPF | 不行；WSL2 也不行（BTF/CO-RE 支持不完整）——一切在本机虚拟机里做 |

## 三、备选方案：云虚拟机（赛前采数据用）

为什么保留：笔记本环境有噪声（宿主程序抢资源、降频、温控），**答辩的 benchmark 数据建议在固定云环境采集**。赛前一个月开一台，几十块钱，采完退订。

1. **选厂商：阿里云**（openEuler 官方镜像在 ECS 公共镜像里直接有，控制台对新手友好）。**正确顺序**：注册 → 实名认证 → **学生认证领 ¥300 无门槛券**（https://university.aliyun.com，"云工开物"高校计划，基本覆盖整个比赛周期）→ 再进 ECS 购买页。⚠️ 券不可与产品折扣叠加，下单时确认"本单可用 ¥300 券"再付款
2. **购买关键选项**：

| 配置项 | 建议值 | 说明 |
|---|---|---|
| 机型 | **通用型/独享型 2C4G** | 避开"共享型"，防 CPU steal 污染调度类指标（runqlat 场景） |
| 镜像 | 公共镜像 → **openEuler 24.03 LTS** | 官方镜像，免安装 |
| 系统盘 | 40–60G | 足够 |
| 购买时长 | 按月 | 灵活，随时退 |

3. **安全三件事**（公网暴露，必做）：
   - 建个人用户日常不用 root：`useradd -m -G wheel alice && passwd alice`
   - 安全组入方向规则**只保留 22 端口**，"放行全部端口 0.0.0.0/0"是红线
   - 每周 + 重大改动后打快照（控制台一键）
4. **连接**：`ssh root@公网IP`（不需要端口转发、不受局域网限制）；VSCode Remote-SSH 配置同 §2.6，HostName 换公网 IP
5. **工具链**：同 §2.4 那条命令
6. **防坑**：控制台设**费用告警**；手机日历设"**比赛结束 → 退订**"；云主机上别存与项目无关的个人文件

## 四、开发期与采数据期的切换

1. **开发期（现在 – 赛前一个月）**：三人各自本机 Hyper-V（§二）
2. **采数据期（赛前一个月）**：开一台云主机，benchmark 集中在云上采（§三）；答辩数据环境一致、可信
3. **切换无缝**：代码全在 git 上，本机 → 云 = `git clone` + §2.4 装包，10 分钟
4. **git 是一切的保险**：本机 VM 会坏、云主机会到期，git 上的提交记录死不了——这也是比赛的"过程性资料"评分项
